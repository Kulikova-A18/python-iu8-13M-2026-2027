# РК-2. Разработка аналитического веб-приложения на Streamlit для анализа CVE-инцидентов

## Цель задания
Разработать интерактивное веб-приложение на фреймворке Streamlit, реализующее многопользовательскую систему анализа данных об уязвимостях CVE за период 2014–2026 гг. Приложение должно содержать три функциональные страницы: страницу авторизации/регистрации, страницу настроек и основную страницу с выводом и визуализацией данных.

## Исходные данные
Студенту выдается набор CSV-файлов с записями об уязвимостях — по одному файлу на год (2014–2026). 

Структура полей:

| Поле | Описание |
|------|----------|
| `cve_id` | Идентификатор CVE-YYYY-NNNNN (уникален в пределах года) |
| `date` | Дата внутри соответствующего года |
| `attack_type` | Тип атаки (SQLi, RCE, XSS, Ransomware и др.) |
| `vendor` / `product` | Уязвимый вендор и продукт |
| `cvss_score` | Оценка 0.0–10.0 |
| `severity` | Critical / High / Medium / Low / None |
| `attack_vector` | Network / Adjacent / Local / Physical |
| `access_complexity`, `privileges_required`, `user_interaction` | Метрики CVSS |
| `confidentiality/integrity/availability_impact` | Метрики CVSS |
| `attacker_country` | Страна-атакующий |
| `target_sector` | Отрасль-цель |
| `affected_hosts` | Число затронутых узлов |
| `status` | Exploited / Patched / … |
| `exploit_available` | Yes / No |

## Требования к функциональности

### 1. Страница регистрации/авторизации
- Форма регистрации нового пользователя: логин, e-mail, пароль (с подтверждением).
- Форма входа для существующих пользователей.
- Хранение учётных данных в локальной БД (например, SQLite / JSON / hashed-файл) с хэш паролей (например, `bcrypt` или `hashlib`).
- Валидация ввода: минимальная длина пароля, проверка совпадения паролей, уникальность логина.
- После успешного входа — переход на основную страницу; возможность выхода из аккаунта.
- Защита: страницы приложения недоступны без авторизации (проверка `st.session_state`).

### 2. Страница настроек
Пользователь может настроить параметры отображения и анализа:
- Выбор диапазона лет (2014–2026) и/или конкретных годов.
- Выбор типов атак для фильтрации.
- Выбор уровня критичности (severity) и вектора атаки (attack_vector).
- Настройка порогового значения CVSS (слайдер).
- Выбор отрасли-цели и страны-атакующего.
- Переключатели отображения: показывать ли `exploit_available = Yes`, только эксплуатированные (`status = Exploited`) и т.п.
- Кнопка «Сохранить настройки» — параметры сохраняются в `st.session_state` (опционально — в файл/БД с привязкой к пользователю).
- Кнопка «Сбросить к значениям по умолчанию».

### 3. Основная страница с выводом данных
- Загрузка датасетов за выбранные годы и применение настроек пользователя.
- Вывод KPI-метрик вверху страницы: общее число инцидентов, средний CVSS, число Critical-уязвимостей, суммарное число затронутых узлов и др.
- Интерактивная таблица отфильтрованных данных (с возможностью сортировки, поиска, скачивания в CSV).
- Не менее 4 визуализаций (Plotly / Altair / Matplotlib):
  - динамика числа уязвимостей по годам/месяцам;
  - распределение по типам атак (bar/pie);
  - топ-10 вендоров/продуктов по числу уязвимостей;
  - тепловая карта: `attack_type` × `target_sector` (или карта мира по `attacker_country`).
- Возможность экспорта отфильтрованных данных (кнопка `st.download_button`).
- Отображение текущих активных фильтров (например, через `st.caption` / `st.expander`).

## Технические требования
- Язык: Python 3.10+, фреймворк Streamlit.
- Многостраничность реализовать через `st.Page` / `st.navigation` (Streamlit ≥ 1.36) или через `st.sidebar.radio`.
- Использовать кэширование (`@st.cache_data`) при загрузке датасетов.
- Код структурирован по модулям: `auth.py`, `settings.py`, `analytics.py`, `app.py` (и/или `pages/`).
- Зависимости оформить в `requirements.txt`.
- В корне проекта — `README.md` с инструкцией запуска (`streamlit run app.py`) и описанием.
- Обработка ошибок: пустые выборки, отсутствующие файлы, неверные форматы — не должны «ронять» приложение.

## Этапы сдачи
1. прототип авторизации/регистрации + скелет приложения.
2. страница настроек + загрузка/фильтрация данных.
3. визуализации, KPI, экспорт.

Формат сдачи: ссылка на Git-репозиторий + видео-демонстрация + заполненный `README.md`.
